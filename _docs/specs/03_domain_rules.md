## 2. 거래코드 채번 룰

```
[Prefix][YYMMDD][-N]

예시:
  AZ260514       → 김형준, 2026-05-14, 단건
  AZ260514-1     → 김형준, 2026-05-14, 분할 1번
  AZ260514-2     → 김형준, 2026-05-14, 분할 2번
```

### 규칙
1. **Prefix**: 담당자 고정값 (User 마스터에 저장)
2. **YYMMDD**: 거래 등록일 (또는 계약일)
3. **-N suffix**: 같은 거래의 분할일 때만 부여 (-1부터 시작)
4. **중복 방지**: 같은 prefix+YYMMDD에 이미 거래가 있으면 자동으로 -1, -2 부여

### 채번 시점
- **광고 시작일** 또는 **계약일** 기준 → 사용자 명확화 필요

## 3. 회계 인식 시점 룰

### 3.1 귀속월 (Accrual basis) — 발생주의
| 컬럼 | 인식 시점 |
|---|---|
| **귀속연도 / 귀속월** | **광고 시작월** (또는 광고 종료월) → 명확화 필요 |
| 매출 인식 | 귀속월 |
| 매입 인식 | 결산예정월 (보통 귀속월과 동일 또는 익월) |

### 3.2 통장 기준 (Cash basis) — 현금주의
| 컬럼 | 인식 시점 |
|---|---|
| 매출 인식 | **입금일** |
| 매입 인식 | **지급일(결산일)** |

→ 한국 회계기준은 발생주의지만, **사장 보고용 현금흐름은 통장 기준**으로 보고 싶어함

## 4. 인센티브(성과급) 계산 룰

### 4.1 기본 룰
```
성과급 = 손익(매출금 - 매입금) × 카테고리별 요율
손익은 VAT 제외 기준
요율은 거래 시점의 effective_from 기준 (2025.04.01 변경)
```

### 4.2 특수 룰

#### 4.2.1 해외매체 1/N 분배
```
해외매체 인센티브 15% 중
  → 국내영업팀 (해당 담당자) 15% 중 일부
  → 해외영업팀 5%는 팀 전체 1/N 분배
실제 분배는 손익 × 15%를 N등분 (N = 활성 멤버 수)
```

#### 4.2.2 국내 본부팀 인센
```
국내 본부팀(영업이 아닌 지원/관리) 인센
  = 영업이익(통장 기준) × 일정 비율 / N
  → 본부팀 인원수만큼 1/N
  → 통장 기준이므로 입금 완료된 거래만 반영
```

#### 4.2.3 IP&협찬 — 나린 20% 쉐어
```
IP & 협찬건 거래의 총 수익(손익) × 20%
  → 이나린에게 지급 (담당자 무관)
```

#### 4.2.4 더영 소개건
```
더영(외부 협력자 추정) 소개건
  → 대행 30%, 자사 10% (변경 후 룰 적용)
  → 별도 플래그 필요 (referred_by = "더영")
```

## 5. 자동 집계 룰

### 5.1 월별 손익 (Accrual)
```sql
SELECT
  귀속연도, 귀속월,
  SUM(매출금) - SUM(매입금) AS 매출총이익,
  SUM(매출금) - SUM(매입금) - SUM(판관비) AS 영업이익
FROM deals
WHERE 귀속연도 = ? AND 귀속월 = ?
GROUP BY 귀속연도, 귀속월
```

### 5.2 월별 손익 (Cash)
```sql
SELECT
  YEAR(입금일) AS y, MONTH(입금일) AS m,
  SUM(매출금) - (
    SELECT SUM(매입금) FROM deals
    WHERE YEAR(지급일) = y AND MONTH(지급일) = m
  ) AS 통장기준_매출총이익
FROM deals
WHERE 입금일 IS NOT NULL
GROUP BY y, m
```

### 5.3 십일조
```
영업이익_월 = 매출총이익 - 판매관리비
십일조 = MAX(영업이익_월, 0) × 0.10
```

### 5.4 26년 plan 달성률
```
달성률 = SUM(매출금, 카테고리=X, 귀속연도=2026) / 매출목표(X)
달성치 = SUM(매출금) — VAT 제외
수익 = SUM(손익)
수익률 = 수익 / 달성치
```

## 6. 데이터 무결성 룰

### 6.1 거래 등록 시 검증
- [ ] 거래코드 unique
- [ ] 매출금 >= 0
- [ ] 매입금 >= 0
- [ ] 부가세 = 매출금 × 0.1 (±1원 허용 — 반올림)
- [ ] 총매출금 = 매출금 + 부가세
- [ ] 광고 시작 <= 광고 종료
- [ ] 귀속월은 광고기간 안에 들어가야 함 (또는 광고 시작월과 동일)

### 6.2 상태 전이
```
DRAFT → CONFIRMED (영업 등록 완료)
  ↓
PURCHASED (매입 결산 완료)
  ↓
SOLD (매출 세계발행)
  ↓
PAID (입금 완료)
  ↓
CLOSED (전체 종료)
```

### 6.3 마스터 정비 규칙
- 사업자번호 없는 거래처는 **세금계산서 발행 불가** → 경고
- 결제일 없는 거래처는 입금예정일 자동 계산 불가
- 인센티브 요율 변경 시 effective_from 필수

## 7. 거래처 분류 (Role Tag)

거래처관리 시트엔 명시적 구분이 없음 — 실제 거래 데이터에서 유추:
- **매체사 (Supplier)**: `매입처(상호명)`에 등장
- **광고주 (Advertiser)**: `실광고주`에 등장
- **세계 발행처 (Issuer)**: `거래처명(매출세계 발행처)`에 등장 — 대행사 또는 광고주 본인

→ 동일 거래처가 여러 역할(매체사+광고주) 가능 — **`role_tags`는 다중 태그(array)** 권장

```
counterparty.role_tags = ['media', 'advertiser', 'agency']
```
