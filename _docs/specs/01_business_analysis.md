## 3. 회계 관점 — 통장 기준 vs 귀속월 기준

이게 이 워크북의 **가장 중요한 인사이트**입니다.

엑셀은 같은 거래를 **두 가지 시점**으로 동시에 집계:

| 관점 | 의미 | 사용 컬럼 |
|---|---|---|
| **통장 기준** (Cash basis) | 실제 입금일/지급일에 매출/매입 인식 | `입금일`, `지급일(결산일)` |
| **귀속월 기준** (Accrual basis) | 광고 집행 월에 매출/매입 인식 | `귀속월`, `결산월` |

`매출장표` 시트의 핵심 라인:
- 총매출(통장) / 총매출(귀속월)
- 손익(통장) / 손익(귀속월)
- 매출원가(통장) / 매출원가(귀속월)
- 영업이익(통장) / 영업이익(귀속월)

→ **ERP는 두 관점을 동시에 보여줘야** 함. 한국 회계기준은 발생주의(귀속월)지만, 현금흐름 관리는 통장 기준이 필요.

## 4. 사업 운영의 핵심 워크플로우 (이벤트 흐름)

```
1. 영업/제안 단계
   └─> 거래코드 채번 (담당자prefix + YYMMDD)

2. 계약 체결
   ├─> 광고 기간, 매출금, 매입금 확정
   └─> Deal 생성 (status=DRAFT)

3. 광고 집행 시작 (광고 시작)
   └─> 귀속월 결정

4. 매입 결산 (매체사로부터 세금계산서 수취)
   ├─> 매입용 세계발행일 기록
   └─> 결산여부=완료

5. 매입 지급
   ├─> 지급일 기록
   └─> 매체사 결제 (대부분 익월말)

6. 매출 세금계산서 발행 (광고주에게)
   ├─> 매출용 세계발행일 기록

7. 매출 수금
   ├─> 입금일 기록
   └─> 입금여부=완료

8. 부가세 신고 시
   └─> 부가세 신고 체크
```

**현재 상태값 분포 (원화 563건):**
- 입금여부 = 완료: 331건 (59%), 미입력: 231건 (41%)
- 결산여부 = 완료: 328건 (58%), 미입력: 234건 (42%)
- 세계발행됐지만 미입금: 53건 (외상매출)
- 입금일-입금예정일 평균 갭: **-3.5일** (대부분 예정보다 빨리 들어옴, 중앙값 0일)

## 5. 인센티브(성과급) 룰 — 2025.04.01 개정

`%` 시트 발췌:

| 카테고리 | 기존 | 변경 | 비고 |
|---|---|---|---|
| 해외매체 | 20% | **15%** | 국내팀 15% + 해외영업팀 5% (LA매체 포함) |
| 자사매체 | 20% | **10%** | 한강버스, 외벽 등 영업대행/팬덤/해외 외 |
| 영업대행 | 30% | 동일 | |
| 팬덤매체 | 20% | 동일 | |
| 팬클럽/대행 | 30% | — | (변경표엔 없지만 % 시트엔 0.3) |
| IP / 협찬/자사 / 매입건 | 0% | 0% | 인센티브 없음 |

**특수 룰:**
- "더영 소개건"은 변경건(대행 30%, 자사 10%)으로 처리
- 해외매체 인센은 **1/N** (해외팀 분배)
- 국내 본부팀 인센은 **영업이익(통장 입금기준)의 1/N**
- IP&협찬 거래: **총 수익의 20%를 나린님에게 쉐어**

→ ERP는 **요율 변경 이력**(effective_from)을 가져야 하며, 거래 시점의 요율로 계산해야 함.

## 7. 특수 케이스 / 엣지

### 7.1 보증금·환급
계정항목 = `보증금`, 메모에 `"매입-보증금(환급예정)"`, `"환급예정"` 등
- 효덕개발 압구정 전속외벽 보증금
- 삼연빌딩 후면 전속계약 보증금
- 매출 0 / 매입만 있는 형태로 등록됨
→ 별도 **보증금 관리 모듈** 또는 계정항목으로 추적

### 7.2 상계처리 (Netting)
24건의 메모에 "상계" 언급. 중앙일보에스 케이스: *"상계처리 방식 - 세금계산서 금액에서 수수료 제외한 금액"*
→ 매입처에 줄 돈에서 매출 수수료를 차감해 정산. 별도 입력 흐름 필요.

### 7.3 페이백 (비공식 수수료)
거래처관리에 `비공식수수료` 컬럼 존재. 예시: 전홍 5% 페이백
*"전홍에서 페이백시 세금계산서 발행 필요"* — 페이백 받을 때 세계 발행 필요
→ 공식 세금계산서와 별개로 트래킹

### 7.4 분할 거래 (-N suffix)
156개 거래코드 그룹이 `-1`, `-2` 식으로 분할됨. 최대 1개 거래가 10개로 분할(AZ250910).
- 같은 거래를 여러 매체/광고주에 분배
- 또는 1개 매입을 여러 매출로 쪼개기
→ ERP에서는 **Deal(부모) - DealItem(자식)** 구조 또는 **분할 ID** 컬럼으로 그룹핑

### 7.5 매출 발행처 == 매입처 (54건)
같은 거래처가 발행처도 되고 매입처도 되는 케이스 — 대행사가 중간에 끼어있을 때 발생

### 7.6 외화 거래
원화 시트에 대비 외화는 12건뿐. **알리페이** 수단, 中国(중국) 광고주.
- 매출은 KRW 표시되어 있지만 실제 결제는 USD/CNY
- 환율 적용 시점 불명확 — 별도 컬럼 필요

### 7.7 자사 통장 다중 (`매출장표` 우측 메모)
- `3333197307962 카카오뱅크` — ASKIM 미션펀드
- 입출금/급여/소매업/중사부(원화/외화) 계좌 별도
- 미국법인 한미은행 USD 계좌
→ **계좌별 잔고 트래킹** + 입출금 발생 시 어느 계좌인지 기록 필요

## 8. ERP가 자동화해야 할 집계

엑셀에서 수기로 만들어진 시트들 — ERP 도입 시 **거래 데이터만 정확하면 자동 생성** 가능:

| 자동 집계 시트 | 산식 |
|---|---|
| 월별 수금,결산 | 매출/매입을 입금예정월·결산예정월로 GROUP BY |
| 월별손익 | 매출 - 매입 - 판관비 (귀속월 + 통장 두 관점) |
| 월별매출&매입 | 거래처 × 월 피벗 |
| 상위거래처 | 거래처별 매출/손익 합계 순위 |
| 매출장표 | 통장기준/귀속월기준 매출·원가·이익 |
| 십일조 | MAX(영업이익, 0) × 10% |
| 26년 plan 달성률 | 카테고리별 SUM(매출) / 목표 |

## 9. 결론 — ERP 모듈 우선순위

### 🥇 P0 (MVP)
1. **거래처 마스터** — 사업자번호/계좌/결제일/수수료 정비
2. **거래(딜) 입력·조회** — 원화/외화 통합, 분할 거래 지원
3. **계정항목/카테고리 마스터** — 상품구분, 계정항목 enum화

### 🥈 P1
4. **상태 추적** — 입금예정·결산예정 캘린더, 미입금/미결산 알림
5. **자동 집계 대시보드** — 월별손익, 매출장표 (통장/귀속월 2뷰)
6. **세금계산서 관리** — 매출/매입 세계발행 트래킹

### 🥉 P2
7. **판관비 입력·조회** — 법인/개인카드/현금, 거래항목 분류
8. **성과급 자동 계산** — 요율표 이력 기반
9. **계좌 잔고 트래킹** — 다중 계좌, 외화 포함
10. **26년 plan 달성 트래커**

### 🏅 P3
11. **십일조 자동 계산** + 정기후원 관리
12. **부가세 신고 헬퍼** — 분기별 매출/매입 묶음
13. **거래처 분석** — TOP 거래처, 연간 추이

## 10. 미해결 질문 (사용자 확인 필요)

1. **분할 거래(-N)의 의미**: 매출 분할? 매입 분할? 매체 분할? — 케이스별로 다른 듯
2. **`귀속월`과 `결산월`의 차이**: 귀속월은 광고집행월, 결산월은 매입정산월 — 맞나?
3. **`매출수단`**: 세금계산서/현금영수증/카드결제/알리페이 외 추가 수단?
4. **`매입건` 카테고리**: 보증금 등 비매출성 매입 전용? 별도 모듈로 분리?
5. **외화 거래**: 환율 적용 기준(인보이스 발행일 vs 입금일)?
6. **부가세 신고 체크**: 현재 0건 — 사용 안 하는 컬럼? 신규 도입 예정?
7. **인센티브 1/N 분배**: "본부팀 1/N"의 N은 본부 인원수? 동적 계산?
